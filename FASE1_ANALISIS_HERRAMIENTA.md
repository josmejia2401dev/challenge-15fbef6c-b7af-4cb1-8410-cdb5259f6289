# Fase 1: Análisis de Requisitos y Selección de Herramienta1. Identificación de Datos Candidatos para CachéEn el sistema de gestión de portafolio de inversiones, las consultas de lectura sobre la información consolidada del portafolio representan el mayor volumen de tráfico (read-heavy).Datos Identificados: Perfil de inversión, balance consolidado de activos y composición de portafolio por usuario ('portfolio').Frecuencia de Lectura vs Escenarios de Cambio: La frecuencia de consulta es alta (múltiples lecturas por minuto por cliente), mientras que la tasa de modificación es baja a moderada.Beneficio: Almacenar el portafolio en memoria reduce drásticamente el tiempo de respuesta e impacta positivamente el rendimiento de las bases de datos transaccionales.2. Selección y Justificación TécnicaHerramienta Seleccionada: RedisRazones de la Decisión:Integración Nativa con Spring Boot: Compatibilidad directa con 'spring-boot-starter-data-redis' y las anotaciones estándar '@Cacheable', '@CachePut' y '@CacheEvict'.Flexibilidad en Estructuras de Datos: Permite serializar y almacenar la información del portafolio de forma estructurada.Escalabilidad Futura: Facilita alta disponibilidad mediante Redis Sentinel o Redis Cluster en caso de crecimiento masivo de usuarios.
